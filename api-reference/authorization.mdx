## API Authorization Guide

Every request to the NLPearl.AI API must carry an `Authorization` header. There are two ways to obtain one, and both are accepted on every `/v2` endpoint.

## API Secret Key

Authenticate your requests by including your Account ID and API secret key in the request header. This ensures that your API calls are secure and correctly attributed to your account.

### Authorization Header Format

Include the following authorization header in all your API requests:

```http
Authorization: Bearer AccountId:SecretKey
```

The _**Token**_ must be in the form `AccountId:SecretKey`.

**For example**:

```http
Authorization: Bearer 66552698d60e456235eae520:tWPqr5EEZv2dxqutv58NsCg7NuqGc1tX
```

You can retrieve your Account ID and Secret Key in [our platform](https://platform.nlpearl.ai/app/settings/api).

### Example API Request

Here’s an example of how to set up the Authorization header for an API request using cURL:

```bash
curl -X GET "https://api.nlpearl.ai/v2/endpoint" \
     -H "Authorization: Bearer 66552698d60e456235eae520:tWPqr5EEZv2dxqutv58NsCg7NuqGc1tX"
```

Replace `66552698d60e456235eae520` and `tWPqr5EEZv2dxqutv58NsCg7NuqGc1tX` with your actual Account ID and API secret key.

<Warning>
A secret key carries **full access** to your workspace and cannot be restricted. Keep it server-side, and never share it with a third party — create an [OAuth 2.0 app](/api-reference/oauth) for that instead.
</Warning>

## OAuth 2.0

An OAuth 2.0 app authenticates with its own **Client ID** and **Client Secret** and receives a short-lived access token limited to the **scopes** you granted it. Use it when an integration you do not control needs access to your workspace, or when you want an integration restricted to part of it.

```http
Authorization: Bearer <access_token>
```
